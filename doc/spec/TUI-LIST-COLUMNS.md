# Feature: TUI List Columns

> **Status:** Draft · 2026-09-23
> **Owner:** maintainer
> **Related:** `doc/spec/TUI-UX-TESTING.md`（INV-7、INV-10、INV-14）、チケット `wy22s31p`（60×20 で列幅が入れ替わった不具合）、`uwqh1bld`（クリック領域が画面の外にはみ出す）

## Goal

TUI の一覧（List ビュー）の列幅を、枠の内側の幅、並べ替えに使っている列、表示中の行の ID の長さだけで決める。端末の幅が足りないときは、重要度の低い列から丸ごと隠し、表示する列を途中で切らない。同じ状態なら、描画のたびにも、起動のたびにも同じ列幅になる。列見出しのクリック領域は、描画した見出しの位置と一致する。

2026-09-23 時点では、列の制約を ratatui のレイアウト計算に任せている。枠の内側が 78 桁未満だと制約を満たす列幅が 1 通りに決まらず、ID や STATUS が 5 桁に切れることがあり、どの配分になるかは起動ごとに変わり得る。列見出しのクリック領域は制約の幅をそのまま足して求めているので、描画した見出しとずれ、狭い幅では画面の外に出る。

## Non-goals

- 横スクロール。
- 利用者が表示する列を選ぶこと、列の順序を変えること。
- 狭い幅で日付などの書式を短くすること。
- 一覧以外の表（ThreadDetail のノード表など）。
- `[f]filter:` と `[esc/q]back` のクリック領域（`uwqh1bld` のうち、列見出し以外の部分）。

## Inputs / Outputs

- **入力**
  - W: 一覧の枠の内側の幅（端末の幅 − 2）。
  - 並べ替えに使っている列（`sort_column`）。
  - L: 表示中の行の ID のうち最長のものの桁数。
- **出力**
  - 列ごとの幅。隠す列は幅を持たない。列の間は 1 桁あける。
  - 表示する列ごとの見出しのクリック領域。

### 列幅の決め方

1. **通常の幅**: ID 13、STATUS 11、VIS 5、CREATED 12、UPDATED 12、TITLE 20 以上。列の間の 5 桁を含めて 78 桁なので、W ≥ 78（端末の幅 80 以上）ならこの幅にし、TITLE が残りをすべて使う。2026-09-23 時点の幅と同じ。
2. **詰めた幅**: W < 78 なら、ID を max(8, min(L, 13)) 桁、STATUS 10、VIS 5、CREATED 10、UPDATED 10、TITLE 16 以上にする。STATUS の値は最長 10 桁（`deprecated`）、日付は 10 桁。どの見出しも並べ替えの印（` ▲` / ` ▼`）を付けて収まる。ID は 3.0 の推奨の 8 桁より長いものも切らずに表示する（13 桁を超える分は通常の幅と同じく切る）。
3. **隠す順**: 詰めた幅でも収まらなければ、CREATED → VIS → UPDATED → STATUS の順に、収まるまで列を丸ごと隠す。並べ替えに使っている列は、この順の最後に回す。ID と TITLE は隠さない。
4. **TITLE の幅**: 表示する列の幅と列の間の桁を W から引いた残り全部。
5. **さらに狭いとき**: 4 列を隠しても ID と TITLE 16 桁が収まらなければ、TITLE は残りの幅にする（16 桁未満になる）。W が ID の幅 + 1 以下なら、TITLE は表示せず、ID を min(ID の幅, W) 桁にする。
6. 列幅の合計（列の間を含む）は W 以下になる。レイアウト計算に解の選択を任せる場面は残らない。

例（L = 8）:

| W | 並べ替えの列 | 表示する列と幅 |
|---|---|---|
| 78 以上 | どれでも | ID 13、STATUS 11、VIS 5、CREATED 12、UPDATED 12、TITLE W − 58 |
| 58（端末 60） | UPDATED | ID 8、STATUS 10、VIS 5、UPDATED 10、TITLE 21 |
| 58（端末 60） | CREATED | ID 8、STATUS 10、CREATED 10、UPDATED 10、TITLE 16 |
| 38（端末 40） | UPDATED | ID 8、UPDATED 10、TITLE 18 |
| 38（端末 40） | STATUS | ID 8、STATUS 10、TITLE 18 |
| 20 | UPDATED | ID 8、TITLE 11 |

### 列見出しのクリック領域

- 表示する列ごとに、見出しの行の、その列の左端から列の幅ちょうどの範囲。列の間の 1 桁は含まない。
- 隠した列にはクリック領域がない。
- 一覧の枠に見出しの行が入らない高さ（枠の高さが 3 未満）では、クリック領域を記録しない。
- 見出しをクリックしたときの並べ替えは、2026-09-23 時点と同じ（同じ列なら昇順と降順を切り替え、別の列ならその列の昇順にし、選択を先頭に戻す）。

## Failure modes

- **1×1 などごく狭い端末**: panic しない。クリック領域はフレームの内側に収まる（INV-7）。
- **ID が 13 桁より長い**: 13 桁で切る（通常の幅と同じ）。
- **並べ替えに使っている列が隠れる**（W が小さく、ID と TITLE のほかに 1 列も入らないとき）: 並べ替えの順序はそのまま保つ。その列の見出しはクリックできない。
- **表示中の行がない**: L は 0 とみなし、ID は 8 桁にする。
- **見落としやすい点**: 列幅を変えたのにクリック領域の計算を変えないと、見出しをクリックしたとき別の列で並べ替わる。クリック領域は列幅と同じ値から求める。

## Performance / Safety

描画のたびに列幅を計算するが、列は 6 つで、行の ID の長さを 1 回数えるだけなので、Not load-bearing — no constraint.

## Acceptance tests

1. **AT-1 通常の幅**: 端末 80×24 と 200×60 で、見出しの行に `ID`、`STATUS`、`VIS`、`CREATED`、`UPDATED`、`TITLE` がこの順で、上の規則 1 の位置に描かれる。
2. **AT-2 詰めた幅と隠す順**: 列幅を決める関数に「例」の表の各行の入力を与えると、表のとおりの列と幅を返す。端末 60×20 と 40×12 で一覧を描くと、見出しの行が同じ列と幅になっている。
3. **AT-3 同じ状態なら同じ画面**: 端末 60×20 と 40×12 で一覧を 100 回描き直すと、毎回同じ画面になる（INV-14）。列幅を決める関数を同じ入力で 2 回呼ぶと同じ結果を返す。
4. **AT-4 ID を切らない**: 表示中の行に 10 桁の ID があるとき、端末 60×20 で ID 列が 10 桁になり、ID が切れずに表示される。
5. **AT-5 見出しのクリック**: 端末 40×12、60×20、80×24、200×60 で、表示する各列の見出しのクリック領域の中に、その列の見出しの文字列が途切れずに描かれている。その領域をクリックすると、その列で並べ替わる。隠した列のクリック領域は記録されない。
6. **AT-6 フレーム内**: 不変条件スイートの全サイズ（1×1 を含む）で、列見出しのクリック領域がフレームの内側に収まる。INV-7 の既知の違反 `uwqh1bld` の除外の対象から列見出しを外しても、スイートが通る。
